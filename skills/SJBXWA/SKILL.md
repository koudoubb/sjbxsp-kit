# SJBXWA · 文案结构化改写

## 用途

把「想到哪写到哪」的口语叙述，重排成层次清楚、条目等长、一眼能扫完的文案。改的是**结构与语感**，不是观点：中心思想、判断、立场一字不动；所有数字、专名、案例细节一条不丢。

默认交付是可直接发布的成品文案，不是修改说明。修改说明放在文末、三到五条，简短。

## 何时使用

- 用户给一段话 / 一篇草稿，要求改写、整理、结构化工整、精简
- 用户要把一段内容发到社群、公众号、朋友圈、小红书正文，要求「读起来清楚」
- 用户对同一素材要「再短一点的版本」
- 用户提到 SJBXWA

不适用：从零创作、选题策划、纯翻译、纯校对错别字。

## 五条硬规矩

1. **信息不增不减。** 原文出现的数字（785 条、三种方式）、平台名（视频号、公众号、小程序）、专有说法（「头像越怪，越招人爱」）、括号里的补充、作者的疑问，全部保留。改写时不许顺手加数据、加结论、加「值得关注」这类空评价。
2. **先分层，再落笔。** 原文通常是单流叙述，先判断有几种「话的功能」：铺垫 / 现状 / 主体清单 / 疑问收尾。功能不同的必须切成独立小标题，一层只讲一件事。
3. **条目等长同构。** 清单类内容（变现路径、步骤、要点）全部改成同一句式：**谁（角色）+ 干什么（动作）+ 怎么运转（机制）**。每条一行标题加一句展开，长度控制在相邻条目的 ±30% 内，不许一条两句、一条五句。
4. **一段一意，超三行就拆。** 中文正文单段不超过三行；超过说明混了两件事，拆开或降级成子条目。
5. **删连接词，不删事实。** 「然后」「其实」「不过我觉得」「总的来说」这类口头胶水全删；「不过」「但」在表示转折判断时保留，因为它承载语义。

## 执行流程

1. **提取事实清单。** 逐句列出原文的所有客观信息（数字、名称、机制、路径），命为 A 表；再列出作者的主观判断与提问，命为 B 表。改写后的文案必须能逐条对回 A、B 两表。
2. **定骨。** 从功能出发切 2–4 层，给小标题。常见骨架：
   - 三层：`账号/项目打法` → `变现或执行路径（编号清单）` → `待核实与提问`
   - 两层：`结论或现象` → `拆解（编号清单）`
   - 加一层可选：开头一句 `导语`（一句话说清这是什么、为什么值得看）
3. **写每层。** 导语一句话，不超过 40 字。清单条目按第 3 条规矩统一句式。判断层只留结论，不重复论证。
4. **收尾压缩。** 原文结尾若是「不知道……有谁知道……欢迎交流」，收成「一句判断 + 一句提问」，删掉重复的「不知道」。
5. **回查。** 用自检清单（见下）过一遍，再输出。

## 输出格式

- 小标题用加粗短句（**一、账号打法** 或 **账号打法**），编号用 1./2./3.，不用 `①`「第一、第二」混排。
- 清单条目：`1. **动词短语。** 展开一句。` —— 加粗部分承担信息骨架，扫读时只看加粗也能读懂全文。
- 正文段落之间空一行；不使用表格，除非原文本身就是对比关系。
- 首次交付后另给「主要改动」3–5 条，一条一句，说明结构、句式、结尾各动了什么，不逐字对比。

## 档位

用户没说长度时，按标准版交付，并在结尾提示可出短版。

| 档位 | 篇幅 | 用途 |
| --- | --- | --- |
| 标准 | 原文 80%–100% | 公众号、长贴、社群主贴 |
| 精简 | 200 字左右 | 社群跟帖、朋友圈长文 |
| 极短 | 100 字以内 | 评论区、转发配文 |

压到精简或极短时，优先保留：数字与人名、路径步骤、结尾提问；先删修饰、再删展开、最后才合并条目。**宁可少一条展开，不许少一个事实。**

## 自检清单

- [ ] A 表（事实）每条都能在成品里找到对应
- [ ] B 表（判断与提问）完整保留，未被削弱或夸大
- [ ] 每层只讲一件事，小标题能独立成句
- [ ] 清单条目句式一致、长度接近
- [ ] 没有新增任何原文没有的数据、案例、评价
- [ ] 没有「总的来说」「不得不说」「值得注意的是」这类填充
- [ ] 结尾是判断 + 提问，不是三重重复的「不知道」
