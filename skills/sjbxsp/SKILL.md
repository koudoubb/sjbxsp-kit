# sjbxsp · 动态卡片口播视频

把一份已定稿的口播稿，做成 3–5 分钟的竖屏知识类短视频：画面是 10–14 页动态卡片（大数字、榜单、对比表、重绘的产品界面、成片画面），音轨是整篇一次性生成的配音，字幕白字黑边最多两行、逐帧精确对齐。

## 何时用

- 用户给了逐字稿 / 口播稿 / 一篇文章，要求"做成视频"
- 已有图文卡片，要升级成带口播的动态视频版
- 需要"卡片 + 讲解 + 字幕"这种形式的知识短视频（抖音 / 视频号 / 小红书 / YouTube Shorts）

不适用：纯图文笔记（那是 `SJBX`）、纯剪辑（不要重新渲染卡片）。

## 前置确认（先问，不要直接开跑）

1. **口播稿定稿**：先产出 `speech.txt` 给用户审，确认后再配音。稿子是整片的地基，改稿要重跑对齐与合成。
2. **音色**：优先用用户指定的克隆音色（整篇一次生成）。没有可用 TTS 时用 `edge-tts zh-CN-YunyangNeural` 占位，并在交付时说明——占位音换掉后画面完全不用重渲。
3. **页数**：按稿子段落给 10–14 页，先给一版分镜表（页码 / 标题 / 画面元素 / 对应口播句 / 素材来源）让用户点头。
4. **素材口径**：默认「界面重绘、照片保留」，原片 UI 截图留 0–1 张。如果用户明确要求"用原片那几个界面"，先说清缩进卡片后字会糊（实测 3–4px），拿到同意再破例。
5. **影像段落清单**：分镜表里标出**哪几页必须是原片影像**（节奏演示、机位演示、成片效果、操作过程），先跟用户确认。做完再补是最贵的返工——卡片重排 + 重新合成 + 重新叠加，一轮一小时起。规则见 `references/cutaway.md`。

`cases/` 里是做完的片子，**开工前先翻最接近的那一个**，抄规格不抄文案：

| 案例 | 题材 | 时长 / 页数 | 值得抄的部分 |
|---|---|---|---|
| `cases/2026-10-aibirthday.md` | AI 变现 / 亲子情感，B 站改编 | 4:23 / 14 页 | 三张界面全重绘、全片人称「你」、`:root` 全量色值、页时长表 |
| `cases/2026-10-ting-daily.md` | 出海自媒体 / 拍摄技法，抖音改编 | 6:20 / 14 页 | **四段实拍 27.4%**：两种嵌法参数、整页视频页底版、素材短于页面时的慢放+定格、现场计数版式 |

`slides.html` 里引用素材用相对路径（`shots/xxx.png`、`ui/out/xxx.png`），因为 html 就在 `anim/` 下。

## 工作流

### 0. 素材：界面重绘，照片保留

分镜里出现的画面，先判断是"内容"还是"界面"：

| 类型 | 处理 |
|---|---|
| 成片画面、AI 视频截图、实拍照片、商品图、手绘作品 | **保留原素材**（这类图是证据，重绘反而失真） |
| 后台、表单、聊天、订单列表、文档、APP/网页界面、软件对话框 | **一律重绘**，不用原片截图 |

**配额：每支片原片 UI 截图 0–1 张，默认 0 张。** 一支 14 页的片子里真正需要"界面"的通常只有 2–3 页，把它们重绘掉，其余用成片画面和纯排版就够——不需要为了"看起来有素材"去截一堆界面。

理由很实际：原片截图分辨率低（常见 852×480）、带水印和客户端 UI、字号是真实 app 字号——缩进卡片后实测只剩 3–4px，观众一个字都看不清。重绘可以按"观众能读"定字号，还能把要讲的字段放大。

做法与字号下限见 `references/ui-mock.md`，骨架（手机表单 / 桌面后台 / 手机对话）与截图脚本在 `assets/ui-kit/`。核心四条：

1. **先量槽位再画**：设计尺寸 = 卡片图片槽位尺寸（不是 390×844），1 CSS px = 卡片 1px，2 倍输出
2. 手机界面画成移动端 Web（状态栏 + 地址栏 + 页面），后台画成桌面 Web（深侧栏 + 表格）
3. 字号按"观众能读"定：手机图正文 ≥14–15px、后台表格 ≥19px（画布 px，不是 css 缩放后的值）
4. 界面配色抄卡片的 `:root`，三张图与卡片同色系；图注标「界面示意」

只有确实需要"这个网站长什么样"的真实站点截图时，才用 `ego-browser` 打开实际站点截一张（登录态可直接复用），截完仍要按上面四条裁切、放大、脱敏；并且这支片就不要再放第二张原片 UI 了。

### 0.5 实拍片段（讲"节奏/机位/效果"的页必须是影像）

纯卡片讲不清"几秒切一次镜头""机位怎么换""这个频道长什么样"。这类段落一律嵌原片片段，卡片只做归纳。一支 14 页的片嵌 3–5 段是常态。

三种嵌法（细节、坐标换算、素材不够长的处理，全在 `references/cutaway.md`）：

| 形态 | 用在哪 | 关键点 |
|---|---|---|
| A 嵌框小窗 | 页上还有榜单/占比/步骤要讲 | 卡片刻 `.hole`，视频叠进洞内，圆角蒙版 |
| B 整页视频页 | 这页就是在放片子 | 单独 html 出 **1080×1480** 底版，视频叠满上部 |
| C 全屏视频页 | 原片本身是竖屏全屏 | 视频直接 1080×1480 铺满 |

三条硬性：底版高度 **1480 不是 1920**（字幕在 y≥1500，铺满会盖字幕）；洞的比例必须等于 crop 比例；**叠加放在 compose 之后**、非破坏式跑（`final2.mp4` 备份 → `overlay.sh` → `final.mp4`）。

### 1. 写口播稿 `speech.txt`

从原稿删叙事、留干货，做 TTS 友好改写：

- 数字用汉字（`42 万` → `四十二万`），单位用中文（`$` → `美元`、`RPM` → `每一千次播放`）
- 不写英文缩写与括号（`AI` 视语境写「智能」/保留具名产品）、`I 人` → `不爱出镜的人`、`IP` → `个人品牌`
- 破折号换逗号，**不要写时间码**（会被念出来）
- 频道名、人名等专有名词保留英文原文
- 段落之间空一行（`align.py` 按空行分段，段 = 页）
- **人称统一为「你」**：教程/案例类口播是"对你说话"，原片的作者自述（"我用的是豆包""我在后台能看到"）改成"你可以用豆包""你在后台能看到"。只在开场第一段留一句"我把这套流程拆一遍"建立讲述者身份。改完 `grep -n "我" speech.txt` 逐条过

### 2. 配音

整篇一次生成，输出 `narration.mp3`。不要逐句合成再拼。

### 3. 转写 + 对齐

```bash
whisper narration.mp3 -m medium -l zh --word-timestamps -o asr --output-format json
python <skill>/scripts/align.py --base <project> --split-first 4
```

`--split-first N` 控制第一段拆成几页（封面 + 引入页），其余每段一页。先看输出的页时间轴，确认页数与分镜表一致。

### 4. 写动态卡片 `anim/slides.html`

```bash
cp <skill>/assets/style.css <skill>/assets/engine.js <skill>/assets/subtitle.html <project>/anim/
cp <skill>/assets/slides-template.html <project>/anim/slides.html
```

- 模板是 3 页骨架（封面 / 截图页 / 数据页），按实际分镜增删；占位图换成成片画面或重绘的界面图。
- **顺序：先出重绘图，再排版。** 界面图只出 2–3 张就要先做完（`ui/out/*.png`），因为槽位尺寸由界面定，尺寸定了卡片才能定。
- 每页一个 `<section class="slide" data-i="N">`，N 从 1 连续到页数。
- 元素用 `data-a` 声明动画（`in` / `pop` / `num` / `bar` / `wipe`），`data-d` 声明延迟，数字用 `data-to` + `data-dec`。
- 版式、字号、安全区、配色：读 `references/layout-rules.md`，不要自己发挥。
- 页面内容要和该页对应时间段的旁白一一对应；讲到某产品/某后台/某一步操作时，画面上必须出现具象画面（成片截图或重绘界面），不要只放抽象图标。多格画面**按旁白顺序排**，不按素材拿到的先后排。
- **要嵌实拍的页，先留洞再排字**。洞的宽高定了，crop 才能反推；先排满文字再挖洞，只能缩字号或挤掉内容。整页视频页（形态 B/C）单独写一个 `anim/pNN.html`，同款 `.top` + `h2` + `.lead` + `.hole`，尺寸 1080×1480。
- 短句页容易只占 2/3 高度：撑高卡片、加粗箭头，不要补水词。
- **第一页（封面）双保险**：内容落进 y 240–1680 只是第一层，四边还要再留 ≥ 92px 内边距；背景渐变/光斑要铺满整个画布，安全区外不能留空（否则裁出来是黑边）。改完立刻跑 `check_safe.mjs` 量，别目测。

### 5. 渲染帧

```bash
python <skill>/scripts/render.py frames --base <project> --pages <页数>
```

每页只渲 100 帧（4 秒动效），其余时长由合成阶段用末帧延长。1080×1920 单帧约 0.4–0.5s，12 页约 8–10 分钟。

只改了几页时加 `--from`，例如只重渲封面：`--from 1 --pages 1`。

> `render.py` 是 ego-browser 的外壳。它的 node 环境 `cwd="/"`、拿不到环境变量、也没有命令行参数，所以**参数只能由 Python 写进生成的脚本正文**。不要再写 `SJBX_BASE=... ego-browser nodejs < x.mjs` 这种用法，必然读不到值。

### 6. 字幕

```bash
python <skill>/scripts/gen_subs.py --base <project>
ego-browser nodejs < <project>/anim/render_subs.mjs
```

`gen_subs.py` 做两行均衡断行并生成渲染脚本；`render_subs.mjs` 逐条截图成透明 PNG。

### 7. 合成

```bash
python <skill>/scripts/compose.py --base <project> --audio narration.mp3
```

产出 `build/final.mp4`（含混音）。逐帧 alpha 合成，字幕零漂移。

### 8. 封面

```bash
# 8.1 2 倍超采样渲封面母版
python <skill>/scripts/render.py cover-hd --base <project>
# 8.2 裁 3:4 安全区 + 出上传版
python <skill>/scripts/make_cover.py --base <project> --src anim/cover-hd.png
```

产出 `anim/cover-hd.png`（2160×3840）、`cover-3x4-2160x2880.png`、**`video-cover-1080x1440.jpg`**。上传版宽度不得低于成片宽度（1080），缩到 500 宽会被平台放大、肉眼发虚。

封面要过两层安全区：3:4 裁切区（y 240–1680）+ 区四边再内缩 92px。核查：

```bash
python <skill>/scripts/render.py safe --base <project> --page 1
```

任一元素边距 < 92 即不达标（退出码 2），回去调坐标重渲，别带着贴边发布。

### 9. 自检（必做，不要跳）

- **抽帧核对页序**：按页中点时间抽 12–14 帧，拼联系表逐页看。排序要用显式数值列表，不要 `glob`（见 `references/pitfalls.md`）。
- **界面图可读性**：把重绘的界面图缩到成片里实际占比的宽度看一眼（例如 928px 宽的卡片图缩到 400px 显示），最小字号还能读才算过；读不出就回 `references/ui-mock.md` 提字号、砍字段。
- **原片 UI 配额**：数一下全片用了几张原片界面截图，>1 张要能说出理由。
- **实拍段落抽查**：每段实拍抽首/中/尾三帧，确认洞内无黑边、首尾无黑帧、定格前后不突兀；再确认字幕带（y≥1500）没被盖住。叠加前后总时长必须一致。
- **字幕交叉验证**：用 `whisper -m small` 独立重转一遍，比对字幕起点。注意小模型可能整体偏早约 1.1s（其自身前置填充），要看偏差中位数是否接近 0，必要时用能量起音点复核。
- **断行检查**：搜一下有没有孤字、数字被拆、英文单词被拆。
- **封面安全区**：`check_safe.mjs` 退出码必须为 0；把上传版从服务器下载回来量一遍尺寸，确认是 1080×1440 而不是被平台压缩过。
- 报告实际时长、帧数、分辨率、封面尺寸。
- **收尾归档**：按 `cases/_TEMPLATE.md` 给这支片写一份案例（实测参数、页时长、`:root`、界面清单、新踩的坑），并更新 `cases/README.md` 索引。

### 10. 发布（仅用户明确要求时）

发布到内容后台属于内部流程，不在本仓库范围内（原 `references/publish-video.md` 未随仓库公开）。两条通用经验留在这里：

- 用前端表单实例直接写字段时，**不要往 model 里塞表单没绑定的键**——多一个未知字段就可能让保存接口 500，删掉立刻 200。
- 视频上传通常是**追加**行为，更新已有条目要剔除旧附件路径，并确认没有覆盖同主题的旧内容。

## 硬规则

- 画面 1080×1920、25fps，mp4（h264 + aac，`+faststart`）。
- **原片 UI 截图每支片 0–1 张，默认 0 张。** 有文字的界面（后台/表单/聊天/文档/网页）一律重绘，重绘件字号不得低于 `references/ui-mock.md` 的下限，图注标「界面示意」；成片画面与真实照片保留原素材。
- 重绘界面的配色必须来自卡片 `:root`，不允许界面自带一套色。
- 口播人称统一为「你」，保留的「我」只能是引用原话或开场那一句。
- **讲节奏、机位、界面、成片效果的段必须用原片影像**，不得只用文字卡片概括。全片实拍占比 20–35%。
- **每支片重新定主题色，不要沿用上一支（尤其别默认浅蓝）**。配色跟题材走：情感暖、教程冷、拆解用高对比深色 + 一个荧光强调色。封面要有钩子——大数字 + 三格实拍 + 高对比色带，让人有点的欲望。
- 配色按主题定，全部走 `style.css` 的 `:root` 变量，页面内不写裸色值。
- 字幕白字黑边 4px、最多两行、不超过字幕带高度；不得压到卡片内容（内容区 y 到 1600 为止）。
- 每个数字必须带口径与单位；估算值标注「估算」与依据。
- 封面两层安全区：第一页元素落在 y 240–1680，且四边再留 ≥ 92px 内边距；圆角矩形/色块/插画不得贴边；背景铺满全画布，裁切后不得出现黑边。
- 封面上传版 ≥ 1080 宽（3:4 即 1080×1440），母版 2 倍超采样渲染。
- 音色整篇一次生成；时间轴不手抄，由 ASR + 对齐派生。

## 脚本一览

| 脚本 | 作用 | 关键参数 |
|---|---|---|
| `render.py frames` | 逐页渲染帧序列 | `--pages` `--from` `--fps` `--frames` |
| `render.py safe` | 3:4 安全区四边距核对 | `--page` `--margin`（默认 92） |
| `render.py cover-hd` | 2 倍超采样渲封面母版 | `--scale`（默认 2）`--out` |
| `align.py` | whisper 词时间 → 字幕条目 + 页时间轴 | `--split-first` |
| `gen_subs.py` | 两行均衡断行 + 生成字幕渲染脚本 | — |
| `compose.py` | 逐页合成 + 拼接 + 逐帧 alpha 字幕 + 混音 | `--audio` `--out` |
| `make_cover.py` | 裁 3:4 安全区 + 出上传版 + 黑边检测 | `--src` `--up-width` |

三个 `.mjs` 模板在 `assets/tpl/`，由 `render.py` 填参后临时生成——**不要手改生成物，改模板**。
