# UI 界面素材：默认重绘

**结论先写：有文字的界面，一律重绘。整支片可以一张原片 UI 截图都不用，而且这是首选。**

只有两类画面保留原素材：**成片画面**（AI 视频、实拍效果、作品成品）、**真实照片**（人物、实物、商品、画作）。除此之外——后台、表单、聊天、订单、文档、列表、APP 页、网页——全部按本文重绘。

配额：**每支片原片 UI 截图 0–1 张，默认 0 张。** 超过 1 张就要先证明"这张重绘不出来"（例如真实站点的品牌首页，重绘会失真成假证）。

## 为什么不用截图

| 原片截图 | 重绘 |
|---|---|
| 分辨率受原片限制（常见 852×480），放大就发虚 | 按显示尺寸 2x 输出，任意放大 |
| 带水印、客户端 UI、视频字幕、鼠标指针 | 干净，构图为讲解服务 |
| 字号是真实 app 字号，缩进卡片后**实测只剩 3–4px** | 字号按"观众能读"定，想强调哪个字段就放大哪个 |
| 品牌界面随时间改版，二次复用就过期 | 是示意图，永远成立 |
| 涉及第三方产品界面，观感上像"盗图" | 自己的产品示意，可标「界面示意」 |

## 核心原则：设计尺寸 = 显示尺寸

不要按"手机 390×844"设计再缩小塞进卡片。**先从 `slides.html` 量出图片槽位的宽高**，按这个尺寸设计，写成固定 `width/height`，截图按 2 倍输出。

```bash
# 量槽位：在浏览器控制台或 ego-browser 里跑
[...document.querySelectorAll('.shot img, .shot')].map(e => [e.className, e.getBoundingClientRect()])
```

```
槽位 400×535  →  设计稿 html,body{width:400px;height:535px}  →  输出 800×1070
槽位 928×427  →  设计稿 928×427                            →  输出 1856×854
槽位 330×594  →  设计稿 330×594                            →  输出 660×1188
```

这样 1 CSS px = 卡片里 1px，字号所见即所得，也不用算缩放。**先定槽位、后画界面**——反过来一定会返工。

## 字号下限（最常翻车）

1080 宽竖屏在手机上播放，观众看到的画布缩放系数约 **0.38**（1080 → 410 逻辑像素）。画布上的字号除以 2.6 才是观众实际看到的字号。

| 槽位宽度 | 正文下限 | 标题下限 | 数字/按钮 | 表格行高 | chip 高 |
|---|---|---|---|---|---|
| 300–340（窄手机） | 14px | 18px | 17px | — | 24px |
| 380–430（手机） | 15px | 26px | 18px | — | 26px |
| 900+（桌面后台） | 19px | 22px | 26px | 45px | 26px |

低于这个值的字，在成片里就是一排灰点，不如不放。**宁可少放两列/两个字段**，也不要塞满小字。

推论：
- 桌面后台最多 5–6 列、5–6 行；不要做 12 列的"完整后台"。
- 手机表单最多 3–4 个字段；超出的用滚动裁切表现（底部内容被固定按钮压住是自然的）。
- 表格行高 ≥ 45px，chip 高 ≥ 26px，才撑得住大字号。

## 三种骨架

### A. 手机：做成移动端 Web，不是 App 截图

统一加浏览器外壳，明确"这是客户在手机上打开的网页"：

```
状态栏（9:41 / 信号 / 电池）→ 地址栏（锁图标 + 域名）→ 页面顶栏 → 内容 → 底部固定按钮
```

- 地址栏胶囊 `border-radius:50%`、高 26–34px、域名 11–14px，锁图标用伪元素画。
- 域名要像真域名：`xiaoxing-birthday.party`、`doubao.com`，不要 `localhost`。
- 圆角：外壳 0（由卡片 `.shot` 的 `border-radius` 提供），内部卡片 12–14px。
- 底部固定操作按钮 + 渐变遮罩，是真实移动端的标志性结构。

### B. 手机对话：一条提改 + 一条回执

讲"随时随地改"这类场景时用，**不要画成聊天软件原样**（会变成第三方界面仿冒）：

```
状态栏 → 地址栏 → 会话头（名称 + "任务运行中"绿点）→ 用户气泡（右，渐变底）
→ 助手气泡（左，白底 + 预览缩略图 + 绿色"预览已更新"）→ 系统记录条「已记录到 B-1042 · 修改第 1 次」→ 输入栏
```

- 气泡圆角 14px，靠边那一角压到 5px（右下/左下），这是"真对话"的细节。
- 助手气泡里塞一张真成片缩略图（110–130px 高），比纯文字可信得多。
- 系统记录条用浅底小字，交代"改动落到哪张单"，和旁白的"自动记录"呼应。

### C. 桌面后台：一屏只讲一件事

```
左侧窄栏（72–84px：logo + 3 个菜单）→ 顶栏（标题 + 面包屑 + 搜索 + 头像）
→ 统计条（3–4 格）→ 表格（表头 + 5 行）
```

- 侧栏用深色，主区浅色，形成层次；选中项用主色描边或色块。
- 统计条 4 格用细线分隔，数字用 `DIN Alternate`。
- 状态列一律 chip（圆角胶囊 + 语义色：待制作=黄、制作中=蓝、待确认=紫、已交付=绿）。
- 进度用 5–6px 细条 + 百分比，比纯文字更有"系统在跑"的感觉。

## 配色：跟着卡片主题走

三张界面**共用同一套色变量**，值来自 `anim/style.css` 的 `:root`。不要给界面单独配一套色，否则卡片和界面像两个产品。

```bash
# 做法：把 style.css 的前 12 个变量抄进 anim/ui/ui.css 的 :root
cp <skill>/assets/ui-kit/* <project>/anim/ui/
```

- 主色只用在：选中项、按钮、进度条、金额、关键 chip。
- 底色用主题的 `--paper` / `--tint2`，不要纯白纯灰（会像 PPT 示意而不是产品）。
- 侧栏深色用 `--ink` 而不是纯黑。

## 文案要求

界面里的文字要像真业务，不要"示例文本"：

- 订单号 `B-1042`、孩子小名 `小星`、时间`今天 15:20`、金额 `¥3,840`
- **数据自洽**：30 元 × 128 单 = 3,840 元；进度条 62% 对应"制作中"
- 与旁白一致：旁白说"第 3 个镜头"，界面上出现的就应该是第 3 镜
- 中文标点用全角，句末不加句号（UI 习惯）

## 图注必须诚实

重绘的界面在图注里标「界面示意」，不要写成"原片演示"：

- ✅ `↑ 订单后台（界面示意）：状态、修改次数、进度，一栏看清`
- ❌ `↑ 原片演示后台：共 11 条订单`

封面不放图注。要标"AI 生成"就在图片角落放白色小角标（如「AI 生成成片」），压在图注里会把版面挤乱。

## 生成步骤

```bash
mkdir -p <project>/anim/ui/out
cp <skill>/assets/ui-kit/* <project>/anim/ui/     # ui.css + 三个骨架 + shoot.mjs
# 1) 改 ui.css 的 :root 为本片主题色
# 2) 改三个 html 的尺寸（= 槽位）与文案
# 3) 改 shoot.mjs 的 BASE 与 SHOTS 数组
cd <project>/anim/ui && ego-browser nodejs < shoot.mjs
```

`shoot.mjs` 用「viewport 取 2 倍 + 页面内 `zoom:2`」实现 2x 输出——ego 的 `page.screenshot` 只接受 `scale:"css"`，直接传 `device` 会报错。

```js
await page.cdp("Emulation.setDeviceMetricsOverride", { width: w*2, height: h*2, deviceScaleFactor: 1, mobile: false });
await page.goto("file://" + BASE + "/" + file);
await page.evaluate(() => { document.body.style.zoom = "2"; });
await page.screenshot({ path: out, scale: "css" });
```

注意：`task.page(label)` 只能用已存在的 label（通常是 `p1`），传新名字会报 `page label not found`。脚本必须用 `ego-browser nodejs < script.mjs`（stdin 重定向）执行，`ego-browser nodejs script.mjs` 会把路径当代码跑。
